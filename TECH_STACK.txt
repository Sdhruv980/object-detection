  A dual-layer object detection system with a browser-based frontend and a
  Python command-line backend. Detects objects in images, videos, and live
  webcam feeds. Includes AI scene description, label verification, a bill/
  invoice scanner, and drag-and-drop image upload.

  Two completely independent pipelines exist side by side:

    [A] Browser Frontend  →  index.html + app.js + style.css
    [B] Python Backend    →  detect.py + requirements.txt

================================================================================
  SECTION 5 — AI SYSTEM ARCHITECTURE
================================================================================

  ── Image Detection Pipeline ────────────────────────────────────────────────

    User uploads image
         │
         ▼
    Resize to max 1920px (preserves aspect ratio)
         │
         ▼
    COCO-SSD detects up to 100 boxes (confidence ≥ 0.15)
         │
         ▼
    IF Gemini key is set:
      ├─ Gemini Vision API: verifyDetectionsWithGemini()
      │     · Corrects misclassified labels (e.g. vase → bottle)
      │     · Adds missed small objects (caps, pens, plants...)
      │     · Returns structured JSON with corrections + new boxes
      │     · Uses IoU (Intersection over Union) to avoid duplicates
      │
      └─ Gemini Vision API: describeImage()
            · Sends 768px JPEG as base64 inline_data
            · Returns multi-paragraph natural language description
    │
    ▼
    Draw all boxes on canvas with color-coded labels
    Update Detection Manifest panel (right side)
    Show AI Scene Description panel (right side)

  ── Video Detection Pipeline ────────────────────────────────────────────────

    User loads video file
         │
         ▼
    resetTracking() — clears any previous tracked objects
         │
         ▼
    Async throttled detect loop (replaces naive rAF+async pattern):
         │
         │  Every animation frame:
         │  ├─ If elapsed < 80ms OR detect already running:
         │  │    Draw current smoothed boxes without model call (display stays smooth)
         │  │
         │  └─ If elapsed ≥ 80ms AND model is free:
         │       ├─ Snapshot video frame → offscreen canvas (prevents tearing)
         │       ├─ COCO-SSD detects up to 50 boxes (conf ≥ 0.25)
         │       ├─ applyLabelOverrides() — apply Gemini corrections
         │       └─ updateTrackedObjects() — temporal smoothing engine (see below)
         │
         └─ drawSmoothedBoxes() — render stabilized boxes with fade-out on miss

    Parallel Gemini interval (every 8 seconds):
         ├─ refreshLabelVerification() — updates label correction cache
         └─ refreshDescription() — updates scene description (every 16s)

    ── Temporal Smoothing Engine ──────────────────────────────────────────

    Problem it solves: Without smoothing, boxes flicker every frame because
    each detection is independent — the model gives slightly different box
    coordinates on every frame even for the same still object.

    Algorithm (updateTrackedObjects):
      1. For each new detection, find the existing tracked object with the
         highest IoU overlap of the same class (threshold: IoU > 0.40)
      2. If match found: lerp (linear interpolate) the box position toward
         new detection by alpha=0.35, lerp score by alpha=0.40
         → boxes glide smoothly to new position rather than jumping
      3. If no match: create new tracked object with a unique ID
      4. Unmatched existing objects: increment missCount
         → After 6 missed frames, remove from tracked list
         → While fading: box opacity reduces (globalAlpha fade-out effect)

    Result: Boxes lock onto objects and follow them smoothly. Objects that
    briefly disappear from detection stay visible for up to 6 frames before
    being removed — eliminates flicker from occasional missed detections.

    Key parameters:
      SMOOTH_ALPHA       = 0.35   Box position lerp speed
      SMOOTH_SCORE_ALPHA = 0.40   Confidence score lerp speed
      SMOOTH_IOU_THRESH  = 0.40   Min overlap to match same object
      SMOOTH_MAX_MISS    = 6      Frames before object is removed
      DETECT_INTERVAL_MS = 80ms   Max model call rate (~12 FPS detect)

  ── Webcam Detection Pipeline ───────────────────────────────────────────────

    getUserMedia() → video stream
         │
         ▼
    resetTracking() — clears previous tracked objects
         │
         ▼
    Async throttled loop (same engine as video):
         ├─ Draw live webcam frame every rAF tick (canvas never freezes)
         ├─ If elapsed ≥ 80ms AND model free:
         │    Snapshot → offscreen canvas → COCO-SSD detect (conf ≥ 0.20)
         │    → updateTrackedObjects() temporal smoothing
         └─ drawSmoothedBoxes() on top of live frame

    Background Gemini interval: same as Video pipeline (8s / 16s cycle)

  ── Bill Scanner Pipeline ───────────────────────────────────────────────────

    User loads video containing bills/invoices
         │
         ▼
    fastExtractKeyframes() — 2 to 4 keyframes based on video duration
         │    · Short (<6s):  2 frames at 30%, 75%
         │    · Medium (<18s): 3 frames at 20%, 50%, 80%
         │    · Long (>18s):  4 frames at 15%, 40%, 65%, 88%
         ▼
    Parallel Gemini OCR on all keyframes simultaneously
         │    · BILL_PROMPT requests structured JSON extraction
         │    · Extracts: vendor, bill_number, items, total, address...
         │    · Fallback model chain: gemini-flash-latest → 3.7 → 3.5 → lite
         ▼
    Deduplication check (by bill_number / AWB + vendor + total)
         │
         ▼
    Render formatted bill cards with all extracted fields
    Export as JSON or CSV

  ── Gemini Label Override System ────────────────────────────────────────────

    Running in background during video/webcam:
    · Gemini scans current frame, returns { corrections: [...] }
    · Corrections are cached in geminiLabelOverrides map
    · Every future COCO-SSD prediction passes through applyLabelOverrides()
    · No re-running Gemini for every frame — corrections applied instantly


================================================================================
  SECTION 6 — DETECTION METHODS & TECHNIQUES
================================================================================

  Object Detection
    · Algorithm : Single Shot MultiBox Detector (SSD)
    · Backbone  : MobileNet V2 / Lite MobileNet V2
    · Anchors   : Multi-scale feature maps
    · NMS       : Non-Maximum Suppression (built into COCO-SSD)
    · Threshold : Configurable per mode (CONF_IMG / CONF_VIDEO / CONF_WEBCAM)

  Temporal Smoothing (Video & Webcam — NEW)
    · Method    : IoU-based object tracking + linear interpolation (lerp)
    · Matching  : Hungarian-style greedy IoU match per class per frame
    · Position  : Lerp alpha 0.35 — boxes glide to new position smoothly
    · Score     : Lerp alpha 0.40 — confidence score stabilised over time
    · Miss      : Objects kept for 6 missed frames (fade-out effect)
    · Result    : Eliminates box flicker, boxes lock onto moving objects

  Async Throttled Detect Loop (Video & Webcam — NEW)
    · Max detect rate : ~12 FPS (80ms minimum between model calls)
    · Display rate    : 60 FPS (rAF draws smoothed boxes every frame)
    · Prevents        : Queue buildup from rAF firing faster than model
    · Offscreen snap  : Frame frozen to canvas before detect (no tearing)

  Bounding Box Format
    · COCO-SSD output : [x, y, width, height] in pixel coordinates
    · Gemini output   : [ymin, xmin, ymax, xmax] normalized 0–1000
    · Internal format : [x, y, w, h] in canvas pixel space

  IoU (Intersection over Union)
    · Used in verifyDetectionsWithGemini() — deduplicate Gemini + COCO boxes
    · Used in updateTrackedObjects() — match new detections to tracked objects
    · IoU > 0.45 for Gemini dedup; IoU > 0.40 for temporal tracking
    · Standard metric for box overlap in object detection

  Confidence Thresholds
    · Images  : 0.08  (very low — catches small and low-contrast objects)
    · Video   : 0.25  (balanced — reduces false-positive flicker)
    · Webcam  : 0.20  (slightly lower — compensates for variable lighting)

  Color-Coded Labels
    · Each class gets a stable color from a 22-color palette
    · Colors assigned on first detection, then cached in colorMap{}
    · Same class always shows the same color across all frames
    · Fading boxes (missed frames) rendered with reduced globalAlpha
